# Cerisier

Nim agent harness. Runs locally, talks to any OpenAI-compatible `/v1` backend (Edge, llama-server), serves a web UI and its own OpenAI-compatible API (for Zed).

## Build and run

- Build: `nim c -o:bin/server/cerisier_server src/server/cerisier_server.nim` (or `nimble build`). `nim.cfg` sets `--mm:arc` (ORC cycle-collector crash on nim-#devel).
- The binary finds its root as `getAppDir()/../..`, so it must live at `<root>/bin/server/`. Static files come from `<root>/web/static`, tools from `<root>/tools`, data from `<root>/data`.
- Config: `<root>/config/cerisier.conf` (key=value) and `config/models.json`. See the `.example` files. Secrets: `$CERISIER_API_KEY` (backend), `$CERISIER_SERVER_TOKEN` (clients of our `/v1`).
- `temp/` is generated by `flatten.sh`; ignore it.

## Layout (`src/`)

- `common/types.nim`: tool manifest, tool-call status, model status types.
- `server/config.nim`: `Config`, `ModelEntry` (limits/capabilities per model, Zed `available_models` shape).
- `server/api/client.nim`: async OpenAI client. `streamSse` uses a raw socket (http only, no TLS). Load/unload exist but are gated by `model_management` (default off).
- `server/api/session.nim`: `ChatSession`, builds chat requests, records token usage.
- `server/agent/loop.nim`: the agent loop (`runAgentTurn`), transport-agnostic via `AgentHooks` (`hooks.nim`: `emit`, `askApproval`, `isCancelled`). `subagent.nim` runs sub-agents on the same hooks. `prompt.nim` builds the system prompt.
- `server/tools/`: manifests (`registry.nim`), approval and execution (`executor.nim`, `runner_local.nim`), built-ins (`builtin.nim`: `todo_write`, `write_file`, `read_file`, `list_files`, `spawn_subagent`), and `toolcalls.nim`.
- `server/web/routes.nim`: server-rendered pages plus the `/ws/chat/{id}` WebSocket (events are batched through `TokenQueue`/`runSender`). `server/web/openai.nim`: `/v1/models`, `/v1/chat/completions`.
- `server/db/database.nim`: SQLite via plain SQL. `files/`, `formats/`, `skills/`: uploads, inline markup, skills.
- `web/static/`: `app.js`, `rich.js` (markdown), `math.js`, `style.css`. No build step.

## Conventions and behavior

- Tools are called with text tags, not native tool calls: `<tool_call>{"name": ..., "arguments": {...}}</tool_call>`. Tool scripts print one JSON object `{"ok": bool, "data": ..., "error": ...}`. Manifests: `tools/*.tool.json` (kind `python|shell|nim-binary`, permission `ask|auto|deny`). All tools run locally.
- `/v1/chat/completions`: model `<name>` is passthrough (client owns tools, request relayed as-is); `cerisier/<name>` runs our loop and tools. Agent-mode requests are stateless (new conversation each) and deny `ask` tools.
- The server is a single-threaded async reactor (httpx backend, `asyncdispatch` is polled). Never block in async code: use async HTTP clients, `sleepAsync`, non-blocking pipe reads. `osproc.hasData` blocks.
- Streaming an HTTP reply: write the status line and headers with `ctx.send`, use chunked framing, set `ctx.handled = true`, and read `ctx.request.body` first (it is dropped once writing starts).
- `prologue` exports `parsecfg.Config`; refer to ours as `config.Config` in `routes.nim`.
- Existing databases keep legacy `model_presets` and `tool_calls.location` (NOT NULL, written as `'local'`); nothing else reads them.
- Edit files in place; keep comments to one short line that says what the code can't.

## Known gaps

- Tool results are sent as `role: "tool"` without `tool_call_id` (fine for llama, may be rejected by strict servers).
- No HTTPS to the backend, no image input over the API, no text-tag fallback for passthrough when a model has `tools: false`.
- Future: a Cerisier router with an OpenAI API plus load/unload, in front of Edge and llama.
